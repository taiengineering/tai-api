# TAI Safe SaaS 페이지 리디자인 작업지시서

> 파일: `nexas/service/saas.html` (55KB, taieng 레포 — Cursor 필수)
> 목표: 문제인식→공감→해결→도입 흐름. 실제 화면·다이어그램·이미지를 적극 활용.
> 소비자가 한 페이지에서 서비스를 이해하고 망설임 없이 도입하는 구조.

---

## 설계 원칙

1. **스크롤 = 설득 과정.** 위에서 아래로 내려가면서 문제→공감→해결→증거→도입→가격→행동 순으로 설득.
2. **모든 섹션에 비주얼.** 텍스트만 있는 섹션 금지. 화면 캡처, 다이어그램, SVG, 아이콘 중 하나 이상.
3. **"이거 내 얘기" 순간 만들기.** 겸직 안전관리자가 첫 3초에 "내 상황을 알고 있다"고 느끼게.
4. **CTA는 2곳.** 히어로(상단) + 하단. 중간에 넣지 않음 — 집중을 방해.
5. **현재 페이지의 요금제 섹션, PG 결제 JS는 그대로 유지.** 섹션 순서와 콘텐츠만 변경.

### 섹션3. [전환] 구조의 변화 — "혼자 하는 구조가 문제입니다"

**레이아웃:** AS-IS / TO-BE 비교 다이어그램

**콘텐츠:**
```
헤드라인: "혼자 하는 구조가 문제입니다."
서브: 안전관리자가 "하는 사람"에서 "배분하고 확인하는 사람"으로 바뀌면
     같은 시간에 3배 더 많은 일이 처리됩니다.

[AS-IS 다이어그램]
안전관리자 1명 → 점검 → 기록 → 보고 → 법령확인 → 교육
(모든 화살표가 1명에게 집중)

[TO-BE 다이어그램]
안전관리자 → 배분 → 작업자A(점검) + 작업자B(TBM) + 시스템(기록·법령·알림)
(화살표가 분산)
```

**비주얼:**
- Supabase diagrams 버킷의 기존 SVG 활용 또는 신규 SVG 제작
- AS-IS는 빨간 톤, TO-BE는 파란/초록 톤
- 가운데 큰 화살표 "→ TAI Safe 도입"

### 섹션4. [해결] TAI Safe 핵심 기능 5가지 — 실제 화면 캡처 중심

**레이아웃:** 각 기능을 "문제→해결" 쌍으로. 좌우 교차 배치.

**⚠️ 핵심: 각 기능마다 실제 TAI Safe 화면 캡처를 사용합니다.**

스크린샷 촬영 대상 (safe.taieng.co.kr에서 캡처):
- 대시보드 화면
- 점검 화면 (작업자 모바일 뷰)
- TBM 작성 화면
- 작업요청/승인 화면
- 법령엔진 결과 화면

현재 프로덕션에서 캡처할 수 없는 화면은 HTML 목업으로 대체:

## 기술 구현 사항

### 카운트업 애니메이션 (섹션1, 섹션5)
```javascript
// IntersectionObserver로 뷰포트 진입 시 카운트업
const counters = document.querySelectorAll('.count-up');
const observer = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      const el = entry.target;
      const target = parseInt(el.dataset.target);
      let current = 0;
      const step = Math.ceil(target / 60);
      const timer = setInterval(() => {
        current += step;
        if (current >= target) { current = target; clearInterval(timer); }
        el.textContent = current.toLocaleString();
      }, 30);
      observer.unobserve(el);
    }
  });
}, { threshold: 0.5 });
counters.forEach(c => observer.observe(c));
```
