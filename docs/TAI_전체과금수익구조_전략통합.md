# PART 1. 법령진단 가격 및 구조 전략

## 1. 전체 전략 방향

TAI는 단일 상품 구조가 아닌 다음 흐름으로 설계됨:

```
FREE → 진단 → 유료 진단 → SaaS → 실행/운영
```

**핵심 원칙:**
- 진단 = 고객 유입 및 문제 인식
- SaaS = 실제 수익 모델
- 프리미엄 = SaaS 전환 유도 장치

---

## 2. 서비스별 구조

### 2.1 건설 (Construction)

| 항목 | 내용 |
|---|---|
| 구조 | FREE → 단일 유료 상품 |
| 가격 | 199,000원 |
| 특징 | 선택 구조 없음 / 즉시 결제·즉시 대응 / 점검 항목 생성 포함 (실행형 진단) |
| 포지션 | "현장 대응용 도구" / "감독 대응 및 제출용 리포트 생성" |

---

### 2.2 시설 (Facility)

| 단계 | 가격 | 역할 |
|---|---|---|
| FREE | 0원 | 유입 |
| 베이직 | 49,000원 | 법령 확인 / 선임·점검·신고 리스트 / PDF 리포트 |
| 상위 | 99,000원 | 전체 결과 공개 / 실행 필요 항목 확인 / 결심 단계 |
| 최고단 | 149,000원 | 실무자 활용 단계 / 연결(선임·수선) 진입 |

---

### 2.3 산업 (Industrial)

| 단계 | 가격 | 역할 |
|---|---|---|
| FREE | 0원 | 유입 |
| 베이직 | 79,000원 | 법령 이해 |
| 상위 | 149,000원 | 전체 확인 및 실무 판단 |
| 프리미엄 | 249,000원 | SaaS 진입 전 단계 / 전환 유도 역할 |
| SaaS | 월 79,000원 | 점검 항목 생성 / 일정 자동 생성 / 작업자 배정 / 운영 및 데이터 축적 |

---

## 3. 진단 구조 원칙

- FREE 존재 (입력값 제한 방식 — 결과 제한이 아님)
- SaaS 사용 시 최상위 진단 자동 포함

---

## 4. 가격 구조 전략

```
시설:  49 → 99 → 149
산업:  79 → 149 → 249 → SaaS(79/월)
건설:  199 (단일)
```

**핵심 전략:**
- 약 2배 단위 상승 구조
- 고민 없이 업셀 가능
- SaaS로 자연스럽게 유도

---

## 5. 서비스별 포지셔닝

| 서비스 | 포지션 | 특징 |
|---|---|---|
| 건설 | "지금 바로 대응" | 빠른 결제 / 즉시 사용 |
| 시설 | "관리용 진단" | 중간 난이도 |
| 산업 | "운영 시스템 진입" | 가장 깊은 구조 |

---

## 6. 핵심 설계 원칙

1. 가격으로 설득하지 않는다
2. 구조로 결제하게 만든다
3. SaaS만이 실행 기능을 가진다
4. 프리미엄은 전환용 상품이다
5. 건설은 단일 상품으로 간다

# PART 2. 전체 과금 및 수익 구조

## 1. 전체 구조

TAI는 단일 수익모델이 아닌 3단 구조:

```
1. 진단 (유입)
2. SaaS (핵심 수익)
3. 연결 + 계약 + 문서 (추가 수익)
```

---

## 2. SaaS 구조 ✅ 정책 확정

### 과금 기준
- **시설 단위** (사용자 과금 아님)

### 요금제

| 플랜 | 가격 | 주요 기능 |
|---|---|---|
| BASIC | 79,000원/월 | 공정 단위 관리 |
| PRO | 149,000원/월 | 시설 단위 관리 / 작업자 배정 |
| PREMIUM | 249,000원/월 | 설비·모델 관리 / 자산관리 / 위험예측 / 교육관리 |
| ENTERPRISE | 협의 (월 50만~) | 맞춤 구성 |

### 사용자 정책
- 관리자 1명 기본 포함
- 추가 관리자: 10,000원/월
- 작업자: 무제한 무료

### 핵심 원칙
- SaaS 무료 없음
- 법령진단 SaaS에 포함
- 기능이 아닌 **"관리 깊이"** 기준 과금

| 항목 | 내용 |

| 특징 | 공정 + 작업 통합 구조 / 분리 불가 |

### 향후 정책
- 연간 결제 할인
- 시설 수 할인
- Enterprise 협의 할인

### 원칙
- **상시 할인 없음**
- 조건부 할인만 적용

---

## 5. 인앱 결제 구조

| 항목 | 내용 |
|---|---|
| 역할 | SaaS 외 추가 수익 |
| 대상 | 관공서 자동 제출 / 문서 템플릿 / 설계형 문서 / 교육 |
| 원칙 | 반복 기능 → SaaS / 건별 업무 → 인앱 |

---

## 6. 연결 서비스 구조 (선임 / 수선) ⚠️ 미정

> **현재 미확정 영역입니다. 아래는 검토 중인 방향입니다.**

### 기본 정책 방향
- 요청: 무료
- 제안: 유료 (핵심 수익 — 업체가 견적 제출 시 과금)
- 계약 수수료: 선택형

### 계약 수수료 검토 기준
- 플랫폼 내 계약 시만 발생 (강제 아님)
- 수수료율: 3% ~ 5%
- 최소 수수료: 30만원
- 예시: 2억 공사 → 600만 ~ 1,000만원

### 계약 유형별 수익 구조

| 유형 | 수수료 | 포함 내용 |
|---|---|---|
| 플랫폼 내 계약 | 발생 | 에스크로 / 계약 / 문서 포함 |
| 외부 계약 | 없음 | 제안비만 수익 |

### 기존 플랫폼 대비 차별점

| 플랫폼 | 수익 구조 |
|---|---|
| 숨고 | 리드 판매 |
| 크몽 | 거래 수수료 |
| **TAI** | SaaS 기반 운영 + 법령 기반 요청 생성 + 증빙·기록 중심 |

---

## 7. 핵심 수익 구조 우선순위

```
1. SaaS          → 고정 반복 수익
2. 제안 과금     → 연결 수익
3. 계약 수수료   → 추가 수익 (선택형)
4. 문서·증빙     → 고마진 장기 수익
```

---

## 8. 전략 핵심 원칙

1. 사용자 과금하지 않는다
2. **시설 단위로 과금한다**
3. **SaaS가 중심이다**
4. 연결은 보조 수익이다
5. 계약 수수료는 선택형이다
6. 문서·증빙에서 장기 수익 발생한다

---

## 9. 최종 한 줄 정리

> TAI는
> "법령 → 운영 → 연결 → 계약 → 증빙"까지 이어지는
> 산업 안전관리 통합 시스템이다
