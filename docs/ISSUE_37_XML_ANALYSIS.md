## 2. `<조문단위>` 트리 구조 (건축법 / 산업안전보건법)

### 2-1. 개수 비교

| 지표 | 건축법 | 산업안전보건법 |
|------|--------|----------------|
| `root.findall(".//조문단위")` | 178 | 208 |
| `root.findall(".//조문/조문단위")` | 178 | 208 |
| `<조문>` 직계 자식 중 `조문단위` | 178 | 208 |
| **부모가 `조문단위`인 중첩 `조문단위`** | **0** | **0** |

**결론 (이번 샘플 한정):** 법제처 현행 XML에서는 `<조문>` 바로 아래의 조문단위만 존재하며, **항/호/목 안에 또 다른 `<조문단위>`가 중첩되는 패턴은 관측되지 않았다.**  
따라서 DB에 관측된 대량 “파편”의 **주원인이 `.//조문단위` descendant 탐색만은 아닐 가능성이 높다** (다른 법령·구버전 XML·과거 저장 raw와 교차 검증 권장).

## 3. `조문키` 고유성

| 법령 | 중복 `조문키` (2회 이상 나타남) |
|------|--------------------------------|
| 건축법 | 없음 |
| 산업안전보건법 | **5건** (`0014000`, `0058000`, `0080000`, `0104000`, `0125000` — 각 2노드, 동일 `조문번호`) |

산안법은 **동일 키 조문단위가 2개씩** 존재 → DB insert 시 중복 row 유발 가능.  
**옵션 B(키 기준 dedupe, 더 완전한 노드 유지)** 또는 DB 유니크 제약 + upsert가 Pilot 1에서 필요.

## 4. “유효 조문 4%” 휴리스틱과 파서의 불일치 (핵심)

현재 `parse_law_content_xml()`은 `article_text`를 **`jo.findtext("조문내용")`만** 채운다.

건축법 예시 (`조문키=0004071`, 제4조의7):

- `조문내용` 직접 텍스트: 짧은 머리줄만 (~15자 수준).
- 실질 본문: **`<항>` / `<호>` / `<목>`** 하위의 `항내용` 등에 분산.

통계 (동일 178·208개 노드 기준):

| 측정 | 건축법 | 산업안전보건법 |
|------|--------|----------------|
| `len(조문내용)` 만으로 **> 500** | 0 | 0 |
| `len(조문내용)` **< 50** | 151 | 166 |
| 조문내용+항+호+목 **전체 이어붙인 길이 > 500** | 61 | 68 |
| 전체 이어붙인 길이 **중앙값** | ~342 | ~351 |

**결론:** 작업지시서의 `LENGTH(article_text) > 500` 같은 지표는, **지금 파서가 넣는 `article_text` 정의와 맞지 않아** “거의 전부 무효”처럼 보일 수 있다.  
Pilot 1 전에 **(1) 지표를 ‘전체 본문 길이’ 기준으로 재정의**하거나, **(2) `article_text`를 조문내용+항/호/목에서 합성**하는 쪽을 함께 검토해야 한다.

## 5. 수정 옵션 A / B / C 권고

| 옵션 | 내용 | 이번 샘플에서의 효용 |
|------|------|---------------------|
| **A** | XPath를 `./조문/조문단위` 등으로 엄격화 | 중첩이 없어 **현 샘플만 보면 `.//`와 개수 동일** — 단, 다른 법/구스키마 방어용으로는 여전히 유효 |
| **B** | `article_internal_key`(조문키) 기준 dedupe, 더 완전한 노드 유지 | **산업안전보건법 필수** (중복 키 5쌍) |
| **C** | A + B | **권장:** 스키마 변형·중복 키 모두에 대비 |

추가로 코드 차원에서는 **옵션 D(권장, Phase 1-2와 연동):**  
`article_text`(또는 별도 컬럼)에 **조문내용 + 항/호/목 본문을 규칙적으로 합성**해 저장·검증하도록 변경하는 것이, 품질 지표와 운영 목표에 직접 맞는다.

## 6. 건축법 vs 산업안전보건법 구조 동일 여부

- 루트 태그: 둘 다 `법령` → `기본정보` + `조문` 트리.
- `<조문단위>` 나열 방식: 동일 패턴.
- 차이점: **산안법만 조문키 중복 쌍 존재** → Pilot 1 대상(산안법)에서 **dedupe 로직 검증 우선순위 높음**.
