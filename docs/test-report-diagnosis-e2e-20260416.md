### 시나리오 A: 이안전 (안전관리자, 150명 금속가공)

#### ✅ 잘된 점
- FREE→PAID1→2→3 단계별 결제(99K+75K+75K) 구조가 심리적 진입장벽 낮춤
- 최종 rule_count 248건 → 겸직 안전관리자가 엑셀로 해봤을 체크리스트를 시스템화한 가치 명확

#### ❌ 문제점
- 이안전의 role_code가 002(관리자)로 잘못 설정 → 012(안전관리자)로 보정 완료
- FREE tier 입력 3필드만으로 업종별 위험군 세분화 표시 없음
- `has_chemical_substance: true`인데 어떤 화학물질인지 식별 안 됨
- `equipment_inspection_status: '일부 미실시'` → 결제 후에도 불완전한 결과물. 후속 입력 동선 없음

#### → 개선점
1. 업종 × 규모 × 위험공정 3축 매트릭스로 위험도 정교화
2. "1인차" 경계 케이스 전용 플래그 도입
3. 화학물질 boolean → 물질 선택 드롭다운 최소 단계로
4. 입력 불완전 항목에 인앱 추가 입력 동선 제공

#### 💡 아이디어
- **인사변동 연동 알림**: 채용 시 "이 채용이 진행되면 중대재해법 적용 전환" HR 연계
- **경계선 가입자 전용 요금제**: 49인·99인·299인·499인 경계 사업장 대상 "경계 모니터링 플랜" 월 29K

#### 💡 아이디어

## 3. 결과물(result_data JSON) 평가

### ✅ 잘된 점
1. JSON 구조 일관성: `tier`/`applicable_laws`/`risk_summary`/`mandatory_obligations`/`penalty_risk` 공통 키 유지
2. 숫자 구체성: 과태료 금액·규칙 수·점검 주기 추상이 아닌 구체 수치
3. 법령 출처 명시: `"law":"산안법 §42"` 조문 단위 인용

### ❌ 문제점
1. result_html·result_pdf_url 전부 NULL — 실물 리포트 부재 → **FN-05로 대응 예정**
2. Risk summary 4단계 분류 기준 불투명
3. 한글·영문 키 혼재 → **BE-06 v2026.04에서 해결됨**
4. 포맷 비일관 (warnings/urgent_action_items/construction_specific_tips/edge_case_warning) → **BE-06 v2026.04에서 해결됨**
5. rule_count와 obligations 배열 길이 불일치 → **BE-06에서 rule_count_total/rule_count_shown 분리로 해결됨**

### → 개선 (반영됨)
1. result_data JSON 스키마 v2026.04 표준화 → **BE-06 완료**
2. 공통 스키마: headline/obligations/warnings/exposure/inspection_schedule/roi 6개 필드 통일 → **완료**
3. evidence[] 배열 추가 (특허 역추적) → **BE-06 continuation에서 완료**

### 💡 아이디어 (미구현, 향후 참고)
- **"이 리포트로 무엇을 할 수 있는가" 섹션**: 관할 고용노동지청 제출 포맷, 임원 보고용 1장, 현장 게시용 체크리스트 3가지 자동 변환
- **리포트 유효기간 워터마크**: PDF 상단 "이 리포트는 2026-04-16 법령 기준. 만료 예정: 2027-04-16"
- **AI 설명 Q&A 위젯**: 리포트 하단 "이 의무에 대해 궁금한 점?" → LLM API 답변
