## 핵심 결론 (한눈에)
- **근본질환:** 엔진 결과 "단일 계약"이 없어 저장 4·읽기 4·투영 3~4로 파편화 → 한쪽 수정이 도처를 깬다. **작업 무게중심 = 청소가 아니라 계약 정립(OBJ-C1).**
- **엔진 경계 = DB 계약**(테이블 `semantic_clause` 등 + Postgres 함수 `diagnose_clauses_common` 등). 엔진은 외부 워크스트림, 앱은 **계약 버전으로만** 접속.
- **실 제품 볼륨 = 공개/익명 진단 트랙**(anonymous_diagnosis_results 3,409행) — 인증 트랙(FDR 2행) 아님.
- **거버넌스:** 도메인당 SSOT 1개 · 시크릿 env(소스 금지) · 마이그레이션 원자적 · 죽음 판정은 3중 확인(코드참조0+소유확인+런타임미사용).
- **주의:** 백엔드는 service_role로 RLS 우회 → grant/정책 이슈는 **anon 프론트 직결 조회 한정**.
