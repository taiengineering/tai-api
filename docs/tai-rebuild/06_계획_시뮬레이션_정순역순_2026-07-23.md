# 작업계획 시뮬레이션 — 정순 · 역순 (게이트 드라이런)

**작성일:** 2026-07-23 · **대상:** [01 작업계획서 v2](./01_작업계획서_object방식.md)의 의존성 그래프
**방법:** 각 Object를 "선행의존이 모두 완료(게이트 green)됐는가?"만으로 착수 가능 여부를 판정하는 드라이런. 통과 못 하면 그 지점에서 붕괴로 기록.

**의존 요약**
`O0←∅` · `C1←O0(+엔진팀)` · `C2←C1` · `C3←C1` · `C4←O0` · `C5←O0` · `O3←O0` · `O5←C1,C4,C5` · `O6←C5,O5` · `O7←C1,C2` · `O8←O3,O5` · `O9←O6` · `O10←C1,C4,C5,O3,O8`

---

## 1. 정순 시뮬레이션 (위상순 · 웨이브)

**Wave 0 — O0 베이스라인.** 선행 없음 → 착수 가능. 게이트: 3사이트 스모크 + 현행 파편 계약 스냅샷(응답 5종·result_data 키·DB 함수). ✅ 통과 시 "무엇을 안 깨야 하는지"의 기준선 확보. → **이후 모든 게이트의 회귀 판정 근거가 여기서 생김.**

**Wave 1 — C1 · C4 · C5 · O3 (병렬).** 전부 `O0`만 의존 → 동시 착수 가능.
- **C1(키스톤)**: `full_result`(공개 3,409행) 기준 단일 result 계약 v1 + transform 검증화. 게이트: 공개·admin·step1 세 화면이 **동일 계약**으로 렌더 + 위반응답 거부. ✅ → C2·C3·O5·O7·O10의 전제 해제.
- **C4(SaaS SSOT)** / **C5(앱 결합·보안)** / **O3(라우트 순서)**: 서로 독립. ✅ 각자 게이트 통과.
- ⚠️ 주의: C1은 **엔진팀 합의**가 추가 선행(계약이 DB 산출 형태). 이 외부 의존이 Wave 1의 임계 리스크.

**Wave 2 — C2 · C3 · O5.**
- **C2(다운스트림 투영)**, **C3(입력 경로)**: `C1` green → 착수. ✅
- **O5(전체 API 계약)**: `C1,C4,C5` 모두 green → 착수. ✅

**Wave 3 — O6 · O7 · O8.**
- **O7(DB 격리)**: `C1,C2` green → 소유권 확정 후 안전 격리. ✅
- **O8(백엔드 데드코드)**: `O3,O5` green → 계약·라우트 확정 후 고아 ~35 제거. ✅
- **O6(재빌드 은퇴)**: `C5,O5` green → 공유 client·계약 위에서 safe/admin 재빌드. ✅

**Wave 4 — O9 · O10.**
- **O9(프론트 정리)**: `O6` green → 구 트리 제거(안전). ✅
- **O10(CI 게이트)**: `C1,C4,C5,O3,O8` green → 검사할 규칙이 모두 존재 → 게이트 정상 작동. ✅

**정순 결과:** 4~5 웨이브로 **막힘 없이 완주**. 각 게이트의 입력이 직전 웨이브에서 준비됨.
- **임계경로(Critical Path):** `O0 → C1 → O5 → O6 → O9` (≈5 게이트) 및 `O0 → C1 → O5 → O8 → O10`.
- **병목:** **C1**. 12개 중 6개(C2·C3·O5·O6·O7·O8·O10 다수)가 C1에 전이 의존 → C1 지연 시 전체 지연. + C1은 엔진팀 외부 의존.
- **조기 병렬 가능 집합:** {C4, C5, O3} — O0 직후 팀 3갈래 동시 진행으로 처리량 확보.

## 2. 역순 시뮬레이션 (뒤에서부터 착수 시도)

각 Object를 마지막(O10)부터 거꾸로 착수 시도 → 선행 미완으로 게이트가 통과 못 하는 지점을 기록.

| 착수 시도 | 선행(미완) | 게이트 붕괴 내용 |
|---|---|---|
| **O10 CI 게이트** | C1,C4,C5,O3,O8 전무 | 검사 규칙(계약·SSOT·라우트·매니페스트)이 아직 없음 → 게이트가 **현재 전 코드를 위반으로 차단**하거나 검사대상 부재. **붕괴** |
| **O9 프론트 정리** | O6 미완 | 중복 `full-version` 제거 = **유일하게 동작하는 safe 사이트를 삭제** → 운영 중단. **붕괴** |
| **O8 데드코드 제거** | O3,O5 미완 | 계약·라우트 미확정 상태에서 "죽음" 판정 불가 → 계약작업이 아직 쓰는 코드를 삭제 위험. **붕괴/위험** |
| **O6 재빌드** | C5,O5 미완 | 공유 client·계약 없이 재빌드 = **복붙 전역·파편 계약을 그대로 재현**(원래 실패 반복). **붕괴(목적 상실)** |
| **O5 API 계약** | C1,C4 미완 | 엔진 결과 계약·SSOT 미정 상태의 계약 = **현재의 파편 상태를 계약으로 박제**. **붕괴** |
| **O7 DB 격리** | C1,C2 미완 | 소유권 미확정 격리 = **엔진 소유 0행 테이블(semantic_clause 등) 오격리** → 과거 near-miss 재현. **붕괴/위험** |
| **C3 입력 / C2 투영** | C1 미완 | 단일 계약(움직이는 표적) 없이 투영·입력 정합 → 곧 다시 어긋남. **붕괴** |
| **C5 · C4 · O3** | O0 미완 | 베이스라인 없으면 무회귀 증명 불가 → 게이트의 "무회귀" 조건 판정 불능. **대기(O0 전까지 불가)** |
| **C1 키스톤** | O0 + 엔진팀 미완 | 기준선 없이 "3화면 동일렌더" 게이트 증명 불가. **붕괴** |
| **O0 베이스라인** | ∅ | 역순의 맨 마지막에야 착수 가능 — 그러나 이미 위 전부 실패. |

**역순 결과:** **모든 단계에서 게이트 붕괴.** 순서를 바꿔 통과되는 Object가 하나도 없음.

## 3. 결론 (시뮬레이션이 검증한 것)

1. **의존성 그래프가 건전하다.** 역순에서 우연히 통과하는 Object가 0 → 각 게이트의 선행이 실재하며 재배열 여지 없음. (반대로 O0 하나만 의존하는 {C4,C5,O3}는 서로 재배열 가능 = 병렬 여지로 확인됨.)
2. **"청소(O7·O8·O9)"를 뒤로 둔 게 정답.** 역순에서 가장 큰 사고가 청소 조기실행에서 남 — **엔진 테이블 오격리, 유일 safe 사이트 삭제, 나쁜 계약 박제.** 이는 팀이 과거 실제로 밟은 함정(소비자 이관 전 테이블 archive → 500)과 동형.
3. **C1이 단일 병목·단일 위험.** 임계경로에 있고 엔진팀 외부 의존까지 얹힘 → **O0 시점에 엔진팀 계약 협의를 선착수**해 C1 리드타임을 흡수해야 함(권고).
4. **재빌드(O6)는 반드시 C5·O5 이후.** 역순 시 "복붙·파편 계약 위에 재빌드"로 원죄를 반복 → 게이트가 이를 명시적으로 막음(설계 의도 확인).

**권고 실행 순서(정순, 게이트 기준):**
`O0` → (병렬) `C1`·`C4`·`C5`·`O3` → `C2`·`C3`·`O5` → `O6`·`O7`·`O8` → `O9`·`O10`.
단, **C1의 엔진팀 계약 협의는 O0와 동시에 시작**한다.
