# OBJ-06c — 공유 코어 dedup 실태조사·정합

일자: 2026-07-24 · 대상: `taiengineering/tai-admin` · READ-ONLY 조사
목적: api client / auth guard / config의 실제 중복 실태를 근거로 현실적 dedup안 확정(맹목적 공유 패키지화 금지).

## 세 변형의 코어 파일
| 변형 | api client | auth guard | config/env |
|---|---|---|---|
| safe(tadmin) `main` | `tadmin/full-version/assets/js/tai/api.js` (37ba67d5) | `.../tai/auth-guard.js` (9bc09205) | `.../tai-rebuild/config.js` (90c5c76e) |
| legacy admin `main` | `admin/full-version/assets/js/tai/api.js` (60a3196d) | `.../tai/auth-guard.js` (5fdaf744) | tai-rebuild/config.js **없음** → `supabase-config.js`+`globals.js` |
| admin-vue3(LIVE) `feat/admin-rebuild` | `admin-vue3/src/composables/useTaiApi.ts` (c5e9c68f) | `.../useAuth.ts` (e283f24f) | `import.meta.env`(VITE_*), 파일 없음 · `useSupabaseRest.ts` |

## safe ↔ legacy-admin 동일성 = 전부 분기
- **api.js**: 공통 골격(`TAI_API`, `apiCall`, token=access_token, 401)이나 safe=12초 timeout+`apiCallAll`+상대경로 리다이렉트, admin=console.log+절대경로(admin.taieng.co.kr) 리다이렉트. byte-identical 아님.
- **auth-guard.js**: safe=토큰유무+survey 공개예외(상대경로). admin=role 게이트(`ADMIN_ROLES=001/002`)+cross-domain 절대경로. **정책 자체가 다름**.
- **config.js**: safe 전용. legacy admin엔 부재(구조 상이).

## 라이브 앱 공유 여부 = 런타임 공유 없음(독립 재구현)
admin-vue3는 `assets/js/tai/*`를 전혀 import하지 않음. `useTaiApi.ts`는 자체 `class ApiClient`(주석 "ApiClient.js 계약 유지"=계약만 복제), `useSupabaseRest.ts`는 레거시 sbFetch "이식", `useAuth.ts`는 원본 doLogin "이식". 즉 **같은 API 계약을 향한 독립 구현체**일 뿐, 코드 공유 아님.

## 기존 공유 헬퍼
- `sbFetch` → `admin-vue3/src/composables/useSupabaseRest.ts`, `apiErrorMessage` → `useApiError.ts`. **둘 다 admin-vue3 앱 내부 dedup**(#79-80). tadmin엔 Supabase REST 헬퍼 자체가 없고, 에러메시지는 `apiCall` 내부 인라인. 크로스-앱 공유 헬퍼 아님.

## 결론: 크로스-스택 공유 패키지화 불가
1. 스택 불일치(정적 vanilla `<script>` vs Vite/TS 번들·`import.meta.env`).
2. 배포 분리(별도 Cloudflare Pages·도메인·env 주입 방식).
3. 정책 분기가 본질(admin role 게이트·cross-domain redirect vs safe 단순 토큰). 억지 통합 시 회귀 위험.

### 현실적·저위험 액션
1. **legacy admin 은퇴로 자연 해소(최우선)** — safe↔legacy-admin vanilla 분기쌍(api.js/auth-guard.js)은 legacy admin(admin-old)이 admin-vue3로 대체·은퇴 중이므로, **legacy 폴더 제거만으로 vanilla 중복 1세트 소멸**. 신규 통합 불필요.
2. **admin-vue3 내부는 이미 dedup 완료**(sbFetch/apiErrorMessage 승격) — 추가 조치 없음.
3. **남는 중복은 tadmin 내부뿐** — 필요시 tadmin 단일 앱 내부 정리로 국한. tadmin↔admin-vue3 크로스-스택 공유는 시도하지 않음.

→ (5) "공유 패키지화"는 **비적용**으로 판정. 실질 dedup은 **O6-d(레거시 은퇴)** 로 흡수. admin-vue3 engine-monitoring 누락(O6-b 발견)은 별도 admin 확인 항목으로 유지.
