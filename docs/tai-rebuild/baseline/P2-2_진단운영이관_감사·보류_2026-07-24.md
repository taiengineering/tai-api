# P2-2 — 유료진단 결과 → 운영(점검) 이관: 감사·설계 + 보류 결정 (2026-07-24)

## 결정
스코프: **유료 법령진단 결과만** SaaS 운영 앱으로 이관(무료진단은 마케팅 CTA, 이관 안 함). 결정된 설계 UX: 세트+항목 즉시, **일정은 기준일 확정 후**(기존 anchor 흐름).
소스 실측 결과 **데이터가 아직 준비되지 않아 지금 구현하면 "0 세트 / 0 항목"**. → **엔진(leg) 교정 완료 후로 보류.** 코드는 손대지 않음. 아래 설계·블로커로 즉시 재개.

## 블로커 (execute_sql 실측)
1. **마스터룰 테이블 드리프트(선행 버그).** `public.master_building_legal_rules` **부재**(`to_regclass`=null). 실데이터 2,002행은 `master_building_legal_rules_legacy_contaminated`. 기존 `services/inspection_sets_svc`의 `generate_items_for_set`/`generate_all_items`가 없는 테이블을 참조 → **현재 라이브 점검항목 생성도 런타임 실패**. (오픈 전이라 영향 없음이나 별도 수정 필요.)
2. **유료 진단에 rule 데이터 없음.** `diagnosis_rule_results`는 **무료 stage1에만** 채워짐(진단 3건/401행). 유료 **stage2 진단 4건은 rule_result 0행**. 이관할 룰 소스가 비어 있음.
3. **의무타입 필터.** 진단 룰이 `obligation_type='ACTION'` + `inspection_required=false` → 기존 매퍼(`auto_create_inspection_sets_from_diagnosis`)가 전부 필터링(INSPECT/BEFORE_WORK 또는 inspection_required만 통과).

## 확정 설계 (재개 시 그대로)
- **백엔드 신규 라우터** `routers/diagnosis_import.py` — `POST /factories/{factory_id}/import-diagnosis {diagnosis_id}`.
  - 검증: 진단행이 해당 factory 소속 + `factory_diagnosis_results.diagnosis_stage >= 2`(1=무료). 유료 판정은 stage 기준(대안: `/diagnosis/access-check` 계약 기반).
  - 룰 소스: `diagnosis_rule_results`(identity=`rule_code`) → `master_building_legal_rules_legacy_contaminated`(join `rule_id=rule_code`)로 주기·의무유형 획득. **엔진 result_data 본문 미의존**(포맷 변동 안전). ※단 블로커 2로 현재 소스가 비어 있음.
  - 매퍼: 기존 `auto_create_inspection_sets_from_diagnosis(supabase, factory_id, company_id, applicable_rules)` 재사용(입력=raw 마스터룰 shape). 진단 이관은 모든 의무를 세트화하려면 `inspection_required=True` 강제 검토.
  - `source`/`diagnosis_id`: 매퍼가 `source='LEGAL_ENGINE'` 하드코딩·`diagnosis_id` 미기록 → (A) 매퍼에 파라미터 추가 vs (B) 생성 후 `UPDATE inspection_sets ... diagnosis_id` 스탬프. 권장 B(공유코드·dedup 불변).
  - 항목: 세트 생성 후 `generate_all_items(factory_id)` 호출(블로커 1 수정 후 정상).
  - 등록: `router_registry/diagnosis.py` ROUTERS에 `{"module":"routers.diagnosis_import"}` 추가. 라우터 규약: `APIRouter(prefix="/factories", tags=[...])`, `db.supabase_client.get_supabase()`(service-role), 핸들러 내 supabase 획득, 별도 auth Depends 미사용(게이트웨이/토큰 계층).
- **DB 마이그레이션(미실행):** `ALTER TABLE public.inspection_sets ADD COLUMN IF NOT EXISTS diagnosis_id uuid;` (+ 인덱스). `factory_diagnosis_results.id`=uuid.
- **FE 진입점:**
  - **주 = `diagnosis-result`**(vue3) — `factoryId`+`diagnosisId` 이미 보유. 유료일 때만 "이 진단 결과를 운영(점검관리)으로 이관" CTA → `POST import-diagnosis` → 성공 토스트 → `/inspection-anchor`.
  - 보조 = `my-diagnosis` — **주의: 현재 `/quotes/survey/list` 기반이라 행에 `factory_id`/`diagnosis_id`/`diagnosis_stage` 없음.** 여기 버튼 붙이려면 목록 API에 필드 추가 필요. 재개 시 주 진입점(diagnosis-result) 우선.
  - `useTaiApi().request('POST', endpoint, body)` / `useToast().show('success'|'error', msg)`.

## 재개 조건
leg 교정으로 (a) 유료 stage≥2 진단에 rule 데이터(diagnosis_rule_results 또는 안정 산출)가 채워지고, (b) 마스터룰 테이블 드리프트가 해소되면, 위 설계대로 백엔드→마이그레이션→FE 순으로 즉시 구현. 그 전까지 보류.
