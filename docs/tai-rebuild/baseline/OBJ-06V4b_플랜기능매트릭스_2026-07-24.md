## 2. 기능 성격 (price_service_feature)
상위 티어 = "하위 전체 포함(superset)" + 추가. 추가분 대부분은 **서비스·쿼터**(메뉴 아님):
- **코어(전 유료 티어 공통)**: 점검일정 자동생성, 법령 자동판정, D-3 알림, TBM 일지, 위험작업 허가서, 신고서식 자동화, 기록 보관, 개정법 진단.
- **sector 특화**: 설비 수명주기(INDUSTRIAL), 하도급 업체관리·다현장(CONSTRUCTION), 위험성평가 자동화.
- **상위 티어 추가(비메뉴 서비스)**: 전담 매니저/온보딩, API 연동, 기록 무제한, 세팅대행(유료), 맞춤 계약, 경영진 대시보드, 멀티사이트, QR·RFID 점검.

## 4. 결론·권고
1. **level→메뉴 하드 게이팅은 대체로 불필요.** 티어는 규모 가격이고 기능은 superset이라, 코어 메뉴는 전 유료 티어 공통. → **sector 게이팅(O6-V4)이 주 요구를 충족.**
2. **선택적 level 게이팅 후보는 소수**(QR·RFID, 멀티사이트, 경영진 대시보드)이고 "하드 숨김 vs 업셀 표시" 제품결정 필요 → 확정 전 보류 권장.
3. `_gate.minLevel` 훅은 gate.ts에 추가 가능하나, 위 사유로 지금은 미적용.

## 5. FREE 메뉴 (별도 nav 필요)
FREE = SAAS 티어 아님(무료 법령진단 사용자). 메뉴(구 tadmin FREE_MENU_DEFS 기준):
- 대시보드 · **법령진단**(my-diagnosis) · **전문가매칭**(fix-chat, NEW) · 마이페이지(회사정보/계약내역/문의하기).
- 구현: gate.ts에서 `sector==='FREE'`면 별도 FREE nav 배열 반환(현 9그룹 대신). 별도 배열 정의 필요 → 후속(제품 확정).

## 6. ⚠ 이번에 발견·수정한 버그 (V4 정합)
`vue3/src/composables/useAuth.ts`의 `PLAN_MAP`이 실제 tier_code와 불일치했음:
- 옛 키: BASIC/STANDARD/PREMIUM/INDUSTRY_BASIC/FACILITY_* (실존 안 함), sector='INDUSTRY'.
- 실제 plan_code: BUILDING_*/INDUSTRY_STARTER·BUSINESS·PRO·CUSTOM/CONSTRUCTION_*, nav sector=FACILITY/INDUSTRIAL/CONSTRUCTION.
- 결과: FACILITY·CONSTRUCTION 고객 sector가 'INDUSTRY'로 오설정 + 'INDUSTRY'≠'INDUSTRIAL' → **V4 sector 게이팅이 메뉴를 오(誤)숨김**.
- 수정(커밋 `31e147c` gate.ts, `8314a11` useAuth.ts):
  1. gate.ts `normSector`: INDUSTRY→INDUSTRIAL, BUILDING→FACILITY 정규화(방어).
  2. PLAN_MAP: 실제 tier_code → 정확한 sector/level. 미상/무계약 → sector '' (실패-오픈, 전체 노출).
- **잔여 검증**: `/contracts/my`가 반환하는 plan_code 실측(현 tier_code와 동일한지) + 플랜별 로그인 런타임 QA 권장.
