# INC — 하이브리드 앱이 워커 기능 대신 "safe 메인"을 띄움 (2026-07-24)

## 증상
Capacitor 하이브리드 앱(출시본)이 기존 워커 기능 대신 safe 메인(마케팅/데스크톱 랜딩)을 표시.

## 근본 원인
- `safe.taieng.co.kr`는 Cloudflare Pages `taieng-tadmin`이 서빙하며, 빌드 설정 `root_dir=vue3` → **신규 데스크톱 safe(vue3 SPA)** 를 배포.
- 그러나 **완전한 워커 모바일 앱(16화면·OTP 로그인)은 vue3에 없고** 구 `tadmin/full-version/app/`에만 존재. vue3 워커 화면(`worker-check`, `worker-check-construction`)은 QR 딥링크 단건 점검 폼 2개뿐(16기능 중 완전 2·부분 3·없음 11).
- Capacitor `server.url = https://safe.taieng.co.kr/app/index.html`(정상)인데, vue3 빌드에 `/app/`이 없어 `_redirects`의 `/* → /index.html 200` 폴백으로 **데스크톱 SPA 루트("safe 메인")** 가 뜸.
- 부수: 라이브 `/`가 "Vuexy…Template" 기본 타이틀을 보이던 것은 브랜딩 이전 빌드의 **엣지 캐시 잔상**(fresh 재배포로 해소).

## 수정 (재빌드·재심사 불필요)
구 워커 PWA와 의존 자산을 vue3 빌드 산출물의 `/app/`에 **서브트리 graft**(기존 blob 재사용):
- `vue3/public/app` ← `tadmin/full-version/app` (7e5a824c)
- `vue3/public/assets` ← `tadmin/full-version/assets` (450f1e22, `../assets/*` 참조 해소)
- `vue3/public/firebase-messaging-sw.js` ← (55459057)
커밋 `1fbfa8e` (main 직접). Vite `public/`은 그대로 dist로 복사되므로 `/app/*`이 **실파일**로 존재 → SPA 폴백보다 우선 서빙.

## 검증 (배포 후)
- 빌드 success(파일수 초과 없음), 배포 success.
- `GET /app/index.html` → 워커 PWA(“TAI Safe” OTP 인증 + 홈/점검/기록/내정보 16기능). ✅
- `GET /app/manifest.json` → 워커 매니페스트(start_url `/app/index.html`, scope `/app/`). ✅
- `GET /` → vue3 데스크톱 safe(브랜딩 "TAI Safe — 산업안전 AI 플랫폼"), stale 해소. ✅
- 하이브리드 앱은 원격 URL 로드 구조라 **설치본 즉시 정상화**.

## 후속(권장)
- 이 graft는 워커 앱을 vue3 배포 안에 얹어 유지하는 방식. 장기적으로 워커앱을 vue3로 재구축하거나 이 구성을 유지 결정 필요.
- `capacitor.config.ts` `webDir:'tadmin/full-version'`은 레거시 표기(server.url 사용 중이라 무해) — 정리 대상.
- **범위 정정:** 앞선 O6-a/b/c는 `tadmin/full-version`을 라이브 safe로 오인해 분석함. 실제 라이브 데스크톱 safe는 `vue3`. O6 safe 계획은 vue3 기준으로 재수립 필요(단, 워커 PWA는 tadmin 자산이 계속 라이브).
