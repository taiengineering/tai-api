## 2. TAI의 철학 — 이것이 모든 콘텐츠의 뿌리

### 근본 명제: "의지가 아니라 방식의 문제다"

법은 정말 세세한 부분까지 안전점검에 대해 만들어놓은 것들이 많습니다. 그만큼 법을 다 일일이 지키기가 쉽지만은 않습니다.

**그런데 법을 못 지키는 건 사업장의 의지가 부족해서가 아닙니다. 방식이 잘못되었기 때문입니다.**

지금까지의 방식은: 안전관리자 1명이 법을 찾아보고, 엑셀에 정리하고, 종이 체크리스트를 만들고, 직접 점검하고, 서류를 쓰고, 보관합니다. 이 방식으로는 2,080+개 법령 규칙을 지키는 것이 물리적으로 불가능합니다.

**방식을 바꾸면, 법을 지킬 수 있습니다.**

TAI의 방식은 다릅니다:
1. **법령을 사람이 찾지 않습니다.** 시스템이 사업장 조건에 맞는 법령을 자동으로 판정합니다.
2. **점검을 1명이 하지 않습니다.** 작업자 전원이 각자 맡은 항목을 체크합니다.
3. **누락을 사람이 감시하지 않습니다.** 시스템이 미완료 항목을 자동으로 알립니다.

이것이 **법령기반 점검방식** — TAI의 특별한 방식입니다. 이 방식이면 법을 지키면서 안전도 확보할 수 있습니다.

> **"법을 지키기 위한 방식을 바꾸면, 법을 지킬 수 있다."**
> — TAI의 근본 명제

### 왜 방식이 잘못되었는가: "안전과 법의 분리"

현장에서는 **"안전"과 "법"이 별개의 일**로 취급됩니다. 이것이 모든 문제의 시작입니다.

| "법 지키기" (사무실 일) | "안전 지키기" (현장 일) |
|---|---|
| 서류 쓰기, 기록 보관, 보고 | 현장에서 위험 줄이기 |
| 안전관리자가 책상에서 함 | 작업자가 현장에서 함 |
| 점검 기록을 "만드는" 일 | 실제로 "점검하는" 일 |

이 둘이 분리되어 있기 때문에 현실에서는 이런 일이 벌어집니다:
- **서류는 완벽한데 현장은 위험합니다** — 기록만 만들고 실제 점검은 안 함
- **현장은 안전한데 과태료를 맞습니다** — 실제로 관리는 했지만 서류가 없음
- **안전관리자가 서류에 묻혀서 현장에 못 나갑니다** — 법을 지키려다 안전을 놓침

**TAI의 답: 법과 안전을 하나로 합친다.**

현장에서 작업자가 점검하면, 그 기록이 **자동으로 법적 서류가 됩니다.** 법령이 요구하는 점검을 현장에서 바로 하고, 누가 언제 뭘 확인했는지가 자동으로 남습니다. 분리가 아니라 통합. 이것이 TAI가 말하는 **"법령기반 점검방식"**입니다.

### 핵심 철학: "1인 집중 → 전원 참여"

현재 한국의 안전관리 구조는 **안전관리자 1명이 모든 것을 떠안는 구조**입니다.
점검, 서류, 보고, 교육, 법령 확인... 전부 1명이 합니다.
겸직이면 본업 하면서 안전관리까지 해야 합니다.

TAI Safe는 이 구조를 바꿉니다:
- **안전관리자 역할:** "혼자 다 하는 사람" → "할당·모니터링·이상대응하는 사람"
- **작업자 역할:** "점검 대상" → "점검 주체" (5초 만에 체크, 이상 시 자동 알림)
- **시스템 역할:** 법령 판정, 일정 생성, 누적 분석을 자동화

### 근본 신념

> **"작업자가 대충 체크해도, 안 하는 것보다 낫다."**

이 한 문장이 TAI의 모든 설계 원칙입니다. 완벽한 안전관리보다 **전원이 참여하는 불완전한 안전관리**가 사고를 더 많이 예방합니다. 종이에 도장만 찍는 점검은 이상이 발견되어도 관리자에게 올라가지 않습니다. TAI는 이상이 발견되면 자동으로 관리자에게 알립니다.

### 사업의 본질

**법령진단은 SaaS 온보딩 도구일 뿐입니다.** 진짜 핵심은:
- 안전관리 업무를 1인 집중 구조에서 **작업자·그룹 분산 구조로 전환**하는 것
- 전원 참여 체계를 만드는 것
- 안전관리자는 "할당·모니터링·이상대응" 역할로 전환

### TAI 철학 체계 (요약)

```
근본 명제: "의지가 아니라 방식의 문제다"
  ↓
해결 원리: "법령기반 점검방식으로 방식을 바꾼다"
  ↓
구조 전환: "1인 집중 → 전원 참여"
  ↓
설계 원칙: "대충 체크해도 안 하는 것보다 낫다"
  ↓
결과: 법 준수 + 안전 확보 동시 달성
```

## 3. TAI Safe는 무엇을 하는가

### 3.1 법령 엔진 (최대 차별점)

TAI Safe의 핵심 기술은 **조건코드 기반 법령 자동 판정 시스템**입니다.

**작동 방식:**
1. 사용자가 사업장 정보를 입력합니다 (업종, 규모, 위치 등)
2. TAI 법령 엔진이 2,080+개 규칙 DB에서 해당 사업장에 적용되는 법령을 **자동으로 판정**합니다
3. 적용 법령별 의무사항(점검, 보고, 서류 등)이 도출됩니다
4. 이 의무사항을 기반으로 일정, 체크리스트, 알림이 자동 생성됩니다

**경쟁사와의 차이:** 경쟁사는 전부 "문의하기" → 컨설턴트가 수동 확인 → 며칠 후 결과. TAI는 **비로그인, 3분, 무료**로 즉시 결과가 나옵니다.

### 3.2 무료 법령진단 (고객 유입 핵심)

- 회원가입 없이 3분 만에 진단 완료
- 무료 결과는 **완결된 결과**입니다 (빈약하게 보이면 유도행위로 비춰짐)
- "확인하지 못한 영역이 있습니다"로 유료 안내 (가격 비노출 → 필요성 → 버튼 클릭 시 가격)
- URL: https://new.taieng.co.kr/free-diagnosis.html

### 3.3 3섹터 통합

TAI Safe는 **산업(제조·서비스) + 건설 + 건물(시설관리)** 3개 섹터를 하나의 플랫폼으로 커버합니다. 경쟁사는 건설 특화 또는 제조 특화인데, TAI는 전부 됩니다.

### 3.4 현장 운영 기능

| 기능 | 설명 |
|---|---|
| 점검 체크리스트 | 작업자가 5초 만에 정상/이상/보류 체크 |
| TBM (Tool Box Meeting) | 작업 전 안전회의 디지털화 |
| 설비 관리 | 장비별 점검 이력, 정비 요청 |
| 위험성평가 | 법정 위험성평가 작성·관리 |
| 작업 일정 | 법령 기반 점검 일정 자동 생성 |
| 자동 알림 | 이상 발견 시 관리자에게 즉시 SMS/앱 알림 |
| 누적 데이터 분석 | "이 장비 경적 문제 4번째" 같은 패턴 탐지 |
| 날씨 기반 작업중지 | 기상청 API 연동, 폭염/한파/폭우 시 작업중지 경고 |

### 3.5 연결 서비스

TAI는 대행 서비스가 아닙니다. 하지만 필요한 전문가·업체를 **연결**해줍니다.

| 서비스 | 설명 |
|---|---|
| TAI Manager (선임연결) | 안전관리자/안전관리전문기관 매칭 |
| TAI Fix (수선연결) | 설비 정비업체 매칭 |

- 수요자(사업장)는 **무료 매칭**
- 공급자(전문기관/정비업체)만 수수료 부담
- 대행기관은 경쟁자가 아닌 **파트너(공급자)**

## 5. 타겟 고객

### 페르소나 1: 사업주 (최종 결재자)

- **고통:** 중대재해처벌법 처벌 공포, 과태료, 뭘 해야 하는지 모름
- **원하는 것:** "처벌받지 않으면 됩니다"
- **메시지:** 과태료 리스크 → TAI로 예방 → 가격 정당화
- **예시 업종:** 제조업 30~100인, 건물관리 회사, 50억 미만 건설현장

### 페르소나 2: 안전관리자 (실사용자)

- **고통:** 혼자 200개 항목 관리, 서류 쓰느라 안전관리 못함, 겸직 부담
- **원하는 것:** 업무 부담 경감, 법령 변경 자동 알림, 작업자가 직접 체크
- **메시지:** "혼자 버티지 마세요. 구조를 바꾸세요."
- **속마음:** "나만 열심히 하고 아무도 안 도와줌" → TAI가 전원 참여 구조로 전환

### 페르소나 3: 시설관리자 / 건물관리 담당자

- **고통:** 소방·전기·승강기 등 다종 법령 파악 어려움
- **원하는 것:** 우리 건물에 뭐가 적용되는지 한눈에 보고 싶음
- **메시지:** "3분 진단으로 확인하세요"

### 금지 프레이밍

- "TAI가 안전관리를 대행합니다" → **TAI는 안전관리 도구입니다**
- "대행기관보다 싼 대안" → **비교 대상은 엑셀+종이+과태료 리스크**
- "더 많이 입력하면 더 정확" → **"해당 법령이 추가 적용됩니다"**
- 무료 결과를 빈약하게 표현 → **무료 결과는 완결된 결과 + 추가 영역 안내**

### 본인인증 관련 표현

- "회원가입" "로그인" **사용 금지**
- 대신: **"사업장 정보 보호"** 프레이밍 사용
