# 조문 코드 체계 조사 결과 (2026-04-23)

## 사용자 원칙

> "많이 나오는건 괜찮지만 놓치는건 안된다.
>  지금 조문코드가 없는것에 대한 대체코드라도 있어야 연결들이 다 됩니다.
>  먼저 실제 코드가 없는것인지. 아니면 체계가 다른것인지를 먼저 조사해주세요."

## 결론 먼저

**"코드가 없는 것이 아니라 체계가 다른 것"**

법제처 자체가 `<조문형식여부>` 태그로 3가지 체계를 명시적으로 구분하고 있다.
그런데 현재 파서가 체계 B와 C를 제대로 처리 못 해 **4,354개 항목을 놓치고 있음**.

## 3가지 체계 식별

### 체계 A: 일반 법령
```
대상: LAW, ENFORCEMENT_DECREE, ENFORCEMENT_RULE (104개)
XML: <조문단위 조문키="0001001">
식별자: 법제처 공식 조문키 (7자리 숫자)
        예: 0001001 = 제1조, 0038021 = 제38조의2
현재 상태: ✅ 완벽 (9,796개 정확히 저장)
```

### 체계 B: NFPC (화재안전성능기준)
```
대상: NOTICE (공고) 37개 + STANDARD 1개
XML: <조문형식여부>Y</조문형식여부>
     <조문내용>제1조(목적)...</조문내용>
     <조문내용>제2조(적용범위)...</조문내용>
식별자: 조문키 없음. "제N조" 텍스트 패턴만 존재.
현재 상태: ❌ 심각 - 37개 법령이 "전문 1개"로 통합 저장됨
놓친 규모: 448개 조문 (485 실제 vs 37 저장)
```

### 체계 C: NFTC (화재안전기술기준)
```
대상: STANDARD 40개
XML: <조문형식여부>N</조문형식여부>
     <조문내용>1. 일반사항 / 1.1 적용범위 / 1.1.1 ...</조문내용>
식별자: 법제처 선언 "조문 아님". 섹션 계층 번호가 사실상 식별자.
        예: 1.7.1.11 = NFTC 102의 분기배관 정의
현재 상태: ⚠️ 중분류(1.1)만 분할. 세부(1.1.1, 1.7.1.11) 놓침.
놓친 규모: 3,906개 세부섹션 (5,046 실제 vs 1,140 저장)
```

## 왜 놓치고 있었나

### NFPC 문제 원인
```python
# 현재 admrul 파서 로직
full_text = root.findtext("조문내용", "") or ""  # 첫 번째만!
```
→ `<조문내용>`이 여러 개일 때 첫 번째만 가져옴
→ 심지어 그것도 폴백으로 전체 텍스트 수집 후 섹션 분할 시도
→ NFPC는 "1.1" 패턴 없어서 분할 실패 → 전체가 "전문 1개"로 저장

### NFTC 문제 원인
```python
# 섹션 분할 정규식
m = re.match(r'^(\d+)\.(\d+)(?!\.\d)\s*(.*)$', line_stripped)
```
→ "1.1"만 인식, "1.1.1"은 건너뜀 (negative lookahead)
→ 중분류까지만 분할되고 세부는 본문에 묻혀버림

## 대체 코드 체계 설계

사용자 원칙 "놓치는 건 안 된다" 반영. 체계별로 안정적이고 유일한 코드 부여.

### 체계 A (법령) - 현재 유지
```
article_internal_key = 법제처 공식 조문키 (7자리)
예: 0038001, 0038021
상태: ✅ 재작업 불필요
```

### 체계 B (NFPC) - 재구축 필요
```
article_internal_key = "nfpc-art-{조문번호:03d}"
예: nfpc-art-001 (제1조), nfpc-art-038 (제38조)
     nfpc-art-038-of-002 (제38조의2)

파서 개선:
  <조문내용> 태그 여러 개 순회
  각 내용에서 "제N조(제목)" 패턴 추출
  각각을 별도 article로 저장
```

### 체계 C (NFTC) - 재구축 필요
```
article_internal_key = "nftc-sec-{섹션번호}"
예: nftc-sec-1.1 (중분류)
    nftc-sec-1.1.1 (세부, 재구축 후 추가됨)
    nftc-sec-1.7.1.11 (말단)

파서 개선:
  "1.1.1", "1.1.1.1" 등 모든 레벨 섹션 추출
  계층 번호 자체를 식별자로 사용
  각 섹션을 article 또는 paragraph로 저장
```
