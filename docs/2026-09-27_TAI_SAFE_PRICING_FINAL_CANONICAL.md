## 1. 상품 구조 — 최종 확정

TAI Safe는 일반 공개상품 기준으로 **3개 Product Tier** 구조로 한다.

### Tier 1. 관리자형

안전관리자 또는 관리조직이 중심이 되어 사용하는 상품.

**핵심 가치:**

```
사업장 정보
→ 적용 법령
→ 법적의무 자동추출
→ 점검업무 생성
→ 일정
→ 문서
→ 수행
→ 증빙
```

관리자 계정 수 자체는 가격 산정의 핵심 변수가 아니다.  
합리적인 운영상 계정 한도는 둘 수 있으나 **관리자 1명당 추가요금을 받는 구조로 설계하지 않는다.**

**공개 시작가격:**

```
월 149,000원부터
VAT 별도
선불
```

---

### Tier 2. 현장참여형

관리자형의 전체 기능에 더해 현장 근로자가 직접 안전관리 과정에 참여하는 상품.

**대표 참여기능:**

- TBM
- 위험성평가 참여
- 점검 수행
- 작업 확인
- 전자서명/확인
- 위험제보
- 사진/증빙
- 개인 수행이력
- 관리자 통합관제

**공개 시작가격:**

```
월 249,000원부터
+ 계약 현장참여 인원
VAT 별도
선불
```

현장참여형은 단순히 관리자형에 작업자 계정만 추가한 상품으로 정의하지 않는다.

다음의 **운영수준 변화**로 정의한다:

> 안전관리자가 혼자 관리하는 체계
> → 안전관리자와 현장 작업자가 함께 참여하는 안전관리체계

---

### Tier 3. 커스터마이징 (CUSTOM)

CUSTOM은 세 번째 Product Tier다. 자동가격 없음. 별도 견적 전용.

다음과 같은 표준 SaaS 범위를 넘어서는 요구만 별도 견적한다:

- ERP 연동
- API 연동
- SSO
- On-premise
- 대규모 데이터 Migration
- 고객 전용 문서양식
- 별도 업무 Process 개발
- 다법인 특수구조
- 별도 SLA
- 고객사 전용 Custom 개발

표준 TAI Safe 이용에 별도 초기 세팅비를 붙이는 개념과 구분한다.

## 3. 현장참여형 Base

현장참여형은 동일 사업장/규모의 관리자형 Compliance Base에 **현장참여 플랫폼 가치**를 추가한 상위 Tier다.

**원칙:**

```
현장참여형 Base
=
해당 사업장의 관리자형 Compliance Base + 100,000원
```

uplift +100,000원은 사업장별로 각각 적용한다.

다사업장에서 추가 사업장 80% 할인을 적용할 때는 uplift를 포함한 금액에 할인을 적용한다:

```
추가 사업장 현장참여형 금액
= (관리자형 Compliance Base + 100,000원) × 80%
≠ (관리자형 Compliance Base × 80%) + 100,000원
```

**예시:**

```
관리자형 149,000원 → 현장참여형 Base 249,000원
관리자형 299,000원 → 현장참여형 Base 399,000원
관리자형 499,000원 → 현장참여형 Base 599,000원
```

그 위에 계약 현장참여 인원 요금이 추가된다.

## 4. 작업자 과금 — 최종 원칙

작업자 요금은 **현장참여형에서만 적용**한다.

**목표:**

1. 인원이 많아질수록 1인당 추가단가는 하락한다.
2. 총 이용금액은 계속 증가한다.
3. 가격절벽을 만들지 않는다.
4. 305명 고객에게 500명 Pack 구매를 강요하지 않는다.

**구간별 추가단가:**

| 구간 | 단가 (인/월) |
|------|-------------|
| 1~20명 | 3,000원 |
| 21~50명 | 2,500원 |
| 51~100명 | 2,000원 |
| 101~300명 | 1,500원 |
| 301명 이상 | 1,200원 |

**누적구간 방식**으로 계산한다.

**계산 예시:**

100명:
```
20 × 3,000 = 60,000
30 × 2,500 = 75,000
50 × 2,000 = 100,000
합계: 235,000원/월
```

300명:
```
20 × 3,000 = 60,000
30 × 2,500 = 75,000
50 × 2,000 = 100,000
200 × 1,500 = 300,000
합계: 535,000원/월
```

305명:
```
300명 가격 (535,000원)
+ 5 × 1,200 = 6,000
합계: 541,000원/월
```

→ 305명이라는 이유로 500명 Pack을 구매시키지 않는다.

## 5. Pack의 의미

마케팅/UI에서 고객 이해를 돕기 위해 인원 구간을 Pack처럼 표현할 수는 있다.

하지만 **실제 가격엔진은 계약한 실제 현장참여 Capacity를 기준으로 계산**한다.

```
85명 계약 → 85명 가격
305명 계약 → 305명 가격
```

100명 Pack, 300명 Pack, 500명 Pack으로 강제 상향시키지 않는다.

## 6. 선불 원칙

TAI는 후불 Active User 과금 서비스가 아니다. **선불 계약 구조**다.

고객은 계약 시 현장참여 Capacity를 선택하고 해당 금액을 선불 결제한다.

**예:**
```
현장참여 Capacity = 100명
```

계약기간 동안 최대 100명의 참여자를 운영할 수 있다.  
퇴사/교체 등의 이유로 작업자가 바뀌어도 계약 Capacity 안에서는 자유롭게 교체할 수 있다.  
특정 개인에게 라이선스를 귀속시키지 않는다.

---

## 7. 계약기간 중 인원 변경

### 증가

계약 중 Capacity 증가가 필요한 경우:

```
추가 Capacity × 남은 계약기간
```

에 해당하는 금액을 추가 선불 결제한다.

### 감소

이미 선불 결제한 계약기간 중 인원이 감소하더라도 원칙적으로 즉시 환불하지 않는다.  
감소된 Capacity는 다음 계약 갱신 시 반영한다.

세부 환불정책은 별도 이용약관/결제정책에서 정의한다.  
이번 문서에서 임의 확정하지 않는다.

## 8. 추가 사업장 가격

다사업장 고객은 사업장 수가 증가해도 할인율을 계속 키우지 않는다. **고정 할인율**을 사용한다.

**원칙:**

```
첫 번째 사업장 = 정상가격 100%
추가 사업장   = 해당 사업장 정상가격의 80%
```

즉 추가 사업장은 **20% 할인**한다.

사업장 수가 3개, 10개, 50개가 되더라도 기본 할인율을 계속 확대하지 않는다.

**이유:** 추가 사업장마다 다시 다음 관리범위가 생성되기 때문이다:

```
사업장 / 공정 / 설비 / 작업 / 적용법령 / 법적의무 / 점검업무 / 일정 / 문서 / 증빙
```

---

## 9. 서로 다른 가격의 사업장이 있는 경우

가입순서에 따라 총액이 달라져서는 안 된다.

**원칙:**

> 계약 내 가장 높은 정상가격 사업장 1개를 100%로 계산하고,  
> 나머지 사업장은 각자의 정상가격 × 80%로 계산한다.

향후 구현 시 deterministic하게 동일한 결과가 나오도록 해야 한다.  
이번 WO에서는 구현하지 않는다.

## 11. 건설 하도급 구조

건설에서 협력사/관계수급인은 단순 작업자 그룹으로 취급하지 않는다.  
TAI 데이터 관점에서는 독립적인 관리객체로 다룬다.

**예:**

```
건설현장
 ├─ 원청
 ├─ 협력사 A
 │   ├─ 공종
 │   ├─ 작업
 │   ├─ 위험성평가
 │   ├─ TBM
 │   └─ 작업자
 ├─ 협력사 B
 └─ 협력사 C
```

표준형에서는 **협력사 수 자체를 주요 과금축으로 사용하지 않는다.**

**이유:**

- 협력사 증가는 건설현장의 정상적인 운영구조다.
- 작업자가 증가하면 현장참여 Capacity 과금으로 이미 매출이 증가한다.
- 협력사와 작업자를 동시에 강하게 과금하면 이중과금으로 받아들여질 수 있다.

단, 특수 대형현장이나 별도 통합관제가 필요한 경우 Custom / Enterprise 대상이 될 수 있다.

- ERP/API 연계
- 고객전용 업무설계

- Custom 개발

## 13. 법령진단과 SaaS 가격 구분

유료 법령진단은 TAI Safe SaaS와 별개의 독립상품이다.

- **법령진단:** 특정 시점의 사업장 법적 상태와 의무를 분석한 결과물 제공
- **TAI Safe SaaS:** 법적의무를 지속적으로 운영·수행·증빙

SaaS의 초기 세팅비로 법령진단을 해석하지 않는다.

이번 SaaS 가격정본에서 법령진단 가격을 임의 변경하지 않는다.  
법령진단 → SaaS 전환 시 크레딧/할인 정책 역시 별도 결정사항으로 둔다.

## 14. 계약기간 할인

TAI가 선불 서비스라는 원칙은 본 정본에 포함한다.

```

`annual_free_months`, 기간할인 등은 별도 Pricing Policy Addendum 또는 다음 Owner Decision으로 처리한다.

최종 선불 결제액
```

고객이 가격 산출 근거를 이해할 수 있어야 한다. Black Box 견적은 지양한다.

## 18. 가격정책의 핵심 철학

1. TAI는 최저가 전략을 사용하지 않는다.
2. 고객이 납득할 수 있는 가격을 목표로 한다.
3. 안전관리자만 사용하는 고객과 전사적으로 사용하는 고객을 동일하게 과금하지 않는다.
4. 작업자 수가 증가할수록 1인당 단가는 낮아진다.
5. 작업자가 증가해도 총 계약금액은 계속 증가한다.
6. 추가 사업장은 할인하지만 무료에 가깝게 만들지 않는다.
7. 사업장 수가 증가한다고 할인율을 계속 확대하지 않는다.
8. 가격절벽을 만들지 않는다.
9. 관리자를 인당 과금하지 않는다.
10. 표준형 초기 세팅비를 받지 않는다.
11. 현장참여형은 단순 계정 추가가 아니라 운영수준의 Upgrade다.
12. Custom 비용은 표준 SaaS와 분리한다.
