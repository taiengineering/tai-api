# TAI 법령진단 결제·입력 로직 개편 설계서 (합의용 / 코드 변경 없음)

> 본 문서는 **합의를 위한 설계서**다. 코드·DB·운영 변경을 포함하지 않는다.
> 신규 가격정책(V4) 정책안과 **현재 운영 코드의 실제 구현**을 대조하여, 무엇을 어떤 순서로 바꿔야 하는지 합의 기준을 제시한다.
> 현재 구현 사실은 `nexas/free-diagnosis.html`, `tai-api` 코드, Supabase(`vwlahtguyggrhvslabax`) 실측 기반. 미확인은 **[미확인]** 표기.
> 작성: 2026-06-05.

## 0. 한 줄 요약

현재 구현은 **상세입력 → 결제** 순서이고, 신규 정책은 **결제 → 상세입력** 순서다. 순서가 정반대이며, 이것이 이번 개편의 핵심이다.

## 1. 현재 구현 (코드 확인 사실)

### 1.1 현재 Step 구조 (free-diagnosis.html)
```
Step0 본인인증 (KG이니시스)
Step1 섹터 선택 (BUILDING / INDUSTRY / CONSTRUCTION)
Step2 무료 기본정보 입력 → submitFree() → 무료 결과
Step3 무료 결과 + 유료 CTA
Step4 유료: [등급선택] → 상세입력폼(시설·공정·설비) 전부 렌더 → 결제 버튼
Step5 유료 결과 + PDF
```

### 1.2 현재 결제 위치 (문제 지점)
- `loadPaidFlow()` → `loadPaidForm()`이 **시설·공정·설비 상세 입력폼을 먼저 전부 렌더**.
- 사용자가 상세입력을 **다 채운 뒤** `startPayment()` 호출.
- 즉 **상세입력 → 결제** 순서.
- 결제 버튼은 현재 `payPrepModal`(모달)에서 "연동 최종 승인 대기 중" 안내 후 `fix-request.html`로 우회. **실결제 미연동.**
- 결과적으로 **결제 없이 유료 상세입력 화면 전체가 노출**되는 상태.

### 1.3 현재 가격 결정 방식
| 섹터 | 현재 가격 산정 |
|---|---|
| BUILDING | `setVal('total_floor_area')` 시 `fetchPriceTier()` → `GET /diagnosis/price-tier?sector=BUILDING&floor_area=` 로 연면적 기반 가격 표시 (기본정보 단계에서 동작) |
| INDUSTRY | 기본정보 단계 가격 산정 **없음**. Step4 등급선택(BASIC 79,000 / STANDARD 149,000 / PREMIUM 249,000)에서 하드코딩 가격 |
| CONSTRUCTION | 기본정보 단계 가격 산정 **없음**. Step4에서 고정 145,000 하드코딩 |

> 정책이 요구하는 "산업=상시근로자수 / 건설=공사금액 기준 기본정보 단계 자동확정"이 INDUSTRY·CONSTRUCTION에는 없다. BUILDING만 부분 충족.

### 1.4 현재 데이터 저장
- 무료·유료 모두 마지막에 `POST /diagnosis/run` 1회 제출 → `anonymous_diagnosis_results`에 저장.
- 단계별 즉시 저장 **없음**. (정책의 "입력 즉시 진단 DB 저장"과 불일치)

## 2. 신규 정책 (정책안 V4) 핵심

1. 법령진단 = SaaS 체험판 아님. **독립 상품**. 진단 결과만으로 PDF·Excel·자체 운영 가능.
2. 가격은 **최초 기본정보 입력 시 확정** (산업=상시근로자수 / 건물=연면적 / 건설=공사금액).
3. 신규 순서: `가격표 → 진단시작 → 기본정보 → 플랜 자동확정 → 결제 → 시설입력 → 공정입력 → 설비입력 → 분석 → 결과`.
4. **결제는 시설입력 이전**. 결제 후 입력 데이터는 즉시 진단 DB 저장.
5. 시설·공정·설비 입력 구조 = **SaaS 입력 구조와 완전 동일**. 진단 전용 구조 만들지 않음. 진단 후 "SaaS 시작하기" → 재입력 없이 전환.
6. 가격표 = 결제 페이지 아님. **고객 선별 페이지**.

## 4. 신규 플로우 설계 (Step 재정의)

```
[가격표 페이지]  ← 선별용. 결제 버튼 아님
      │  "진단 시작"
      ▼
Step0  본인인증 (현행 유지)
      ▼
Step1  섹터 선택 (현행 유지)
      ▼
Step2  기본정보 입력
        - 산업: 업종 / 상시근로자수 / 사업장면적
        - 건물: 용도 / 연면적
        - 건설: 공사금액 / 공사유형
      ▼
Step3  플랜 자동확정 (가격 표시)
        "귀 사업장은 INDUSTRY BUSINESS · 299,000원 대상입니다"
        ※ 무료 진단을 유지한다면: 여기서 무료결과 먼저 → 유료 전환 분기 (5.2 참조)
      ▼
Step4  결제  ← ★ 위치 이동의 핵심
        - 청약철회 제한 고지 동의 (현행 withdrawal-notice 재사용)
        - KG이니시스 결제
        - 결제 성공 → order_id 확정, 진단 세션 생성
      ▼
Step5  시설(Facility) 입력  ─┐
Step6  공정(Process) 입력    ├ 입력 즉시 저장 (정책 5)
Step7  설비(Equipment) 입력 ─┘
      ▼
Step8  법령분석 (POST /diagnosis/run)
      ▼
Step9  결과 + PDF + Excel
      ▼
[SaaS 시작하기]  ← 재입력 없이 시설/공정/설비 전환
```

### 4.1 무료 진단의 위치 (합의 필요 사항 ①)
정책안은 유료 상품 흐름 중심으로 서술돼 있고 무료 진단의 존속을 명시하지 않는다. 현재는 무료(3회) → 유료 전환 구조다. 두 선택지:

- **(가) 무료 유지**: Step2 기본정보로 무료결과 먼저 제공 → "유료 진단" 선택 시 Step4 결제로. 무료는 기본정보만으로 산출(현행 유지), 유료는 결제 후 시설·공정·설비.
- **(나) 무료 폐지**: 가격표(선별) → 기본정보 → 결제 → 상세입력. 무료결과 단계 제거.

→ **대표 결정 필요.** 정책의 "독립 상품" 기조는 (나)에 가깝지만, 현재 마케팅·유입(무료 3회)이 (가)에 묶여 있다.

### 4.2 결제 후 입력 중단 시 처리 (합의 필요 사항 ②)
결제 후 시설·공정·설비 입력 중 이탈 시: 결제는 완료됐으나 분석 미완. 처리 방식:
- 세션 저장 후 재진입 허용(이메일·토큰으로 이어하기), 또는
- 입력 미완 상태로도 부분 분석 제공.

→ **대표 결정 필요.** (결제-입력 순서가 바뀌면서 새로 생기는 케이스)

## 5. 작업 분해 (3층) — 코드 변경 시 범위

### A층 — 프런트 플로우 재배치 (`taieng/nexas/free-diagnosis.html`)
- Step 순서 재정의(4절), 결제 게이트를 상세입력 앞으로 이동.
- 결제 자리(Step4)는 만들되 실 PG 연동은 별도(현재 미연동).
- 영향: 운영 사이트 1파일. Claude가 브랜치+PR로 작업 가능.
- 선결: 4.1·4.2 합의.

### B층 — 가격 자동산정 API (`tai-api`)
- 현재 `GET /diagnosis/price-tier`(BUILDING 전용)를 3섹터로 확장:
  - INDUSTRY: 상시근로자수 구간 → 플랜·가격
  - CONSTRUCTION: 공사금액 구간 → 플랜·가격
  - BUILDING: 연면적(현행 유지)
- 가격 소스: 기존 `price_diagnosis_report` / `price_policy` 테이블 활용 가능성 검토(현재 구조 [미확인 — 다음 단계에서 컬럼 확인]).
- 영향: tai-api 라우터/서비스. Claude가 브랜치+PR로 작업 가능.

### C층 — 시설·공정·설비 공통모델 + SaaS 연계 (`tai-api` + DB)
- 진단 입력을 SaaS 테이블과 통일. 현재 SaaS 측 존재 테이블(실측):
  `runtime_facility_profile`, `factory_process`, `equipment_assets`, `process_equipment_map`, `facility_condition`, `runtime_facility_equipment`, `v_facility/process/equipment` 뷰 등.
- 진단 시 입력 → 위 테이블에 즉시 저장 → "SaaS 시작하기" 시 동일 레코드 승계(재입력 금지).
- 결제 후 진단 세션 ↔ factory_id 연결 구조 설계 필요(현재 무료/유료는 anonymous, factory_id 없음).
- 영향: **DB 스키마 + 엔진 입력 경로 + SaaS 동시.** 법해석·엔진 구조와 얽혀 **GPT(엔진/스키마 담당)와 분담 필요.** Claude 단독 운영 DB 적용은 보류 권장.

## 6. 권장 진행 순서 (합의 후)

1. **4.1·4.2 정책 결정** (무료 존속 / 이탈 처리).
2. **A층 프런트 재배치** — 결제 위치 이동 + 신규 Step 골격(결제 미연동 상태로도 흐름 정렬). 가장 가시적이고 위험 낮음.
3. **B층 가격 자동산정** — A층 Step3(플랜 자동확정)이 실제 값을 받도록.
4. **C층 공통모델** — GPT와 분담. 결제 연동(KG이니시스) 완료와 함께.

> A·B는 Claude가 브랜치+PR로 진행 가능. C는 설계 합의 후 GPT 협업.
