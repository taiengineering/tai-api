## 0. 한 줄 요약

현재 구현은 **상세입력 → 결제** 순서이고, 신규 정책은 **(가격결정 정보 입력 → 가격 안내 →) 결제 → 상세입력** 순서다. 순서가 정반대이며, 이것이 이번 개편의 핵심이다. 더불어 **유료진단은 회원 전용**으로 바뀌고, 상세입력은 **SaaS 표준코드 기반(수동입력 없음)**, 응답은 **예/아니오 2종(모름 삭제)**으로 통일한다.

## 1. 현재 구현 (코드 확인 사실)

### 1.1 현재 Step 구조 (free-diagnosis.html)
```
Step0 본인인증 (KG이니시스) — 로그인 여부와 무관하게 항상 수행
Step1 섹터 선택 (BUILDING / INDUSTRY / CONSTRUCTION)
Step2 무료 기본정보 입력 → submitFree() → 무료 결과
Step3 무료 결과 + 유료 CTA
Step4 유료: [등급선택] → 상세입력폼(시설·공정·설비) 전부 렌더 → 결제 버튼
Step5 유료 결과 + PDF
```

### 1.2 현재 결제 위치 (문제 지점)
- `loadPaidFlow()` → `loadPaidForm()`이 **시설·공정·설비 상세 입력폼을 먼저 전부 렌더**.
- 사용자가 상세입력을 **다 채운 뒤** `startPayment()` 호출.
- 즉 **상세입력 → 결제** 순서.
- 결제 버튼은 현재 `payPrepModal`(모달)에서 "연동 최종 승인 대기 중" 안내 후 `fix-request.html`로 우회. **실결제 미연동.**
- 결과적으로 **결제 없이 유료 상세입력 화면 전체가 노출**되는 상태.

### 1.3 현재 가격 결정 방식
| 섹터 | 현재 가격 산정 |
|---|---|
| BUILDING | 연면적 입력 시 `GET /diagnosis/price-tier?sector=BUILDING&floor_area=` 로 가격 표시 (기본정보 단계 동작) |
| INDUSTRY | 기본정보 단계 가격 산정 **없음**. Step4 등급선택(79,000/149,000/249,000) 하드코딩 |
| CONSTRUCTION | 기본정보 단계 가격 산정 **없음**. Step4 고정 145,000 하드코딩 |

### 1.4 현재 입력 응답 타입 (DB `diagnosis_input_fields` 실측)
| field_type | 개수 | 비고 |
|---|---|---|
| tri_state | **58** | 예/아니오/**모름** 3종 → 신규는 모름 삭제 대상 |
| number | 36 | |
| select | 12 | |
| text | 6 | |
| table | 5 | process_list/equipment_list 등 시설·공정·설비 |
| multi_select | 1 | |

### 1.5 현재 데이터 저장
- 무료·유료 모두 마지막에 `POST /diagnosis/run` 1회 제출 → `anonymous_diagnosis_results` 저장. 단계별 즉시 저장 **없음**. 모두 anonymous(회원 미연결).

## 2. 신규 정책 (V4 + 2026-06-05 결정 반영)

### 2.1 가격·상품 기조 (정책안 V4)
1. 법령진단 = **독립 상품**. 결과만으로 PDF·Excel·자체 운영 가능. SaaS는 선택.
2. 가격은 **가격결정 정보 입력 시 확정** (산업=상시근로자수 / 건물=연면적 / 건설=공사금액).
3. **결제 → 상세입력** 순서. 결제 후 입력은 즉시 저장.
4. 시설·공정·설비 입력 = SaaS와 동일 구조, 진단 후 재입력 없이 SaaS 승계.
5. 가격표 = 결제 페이지 아님. **고객 선별 페이지**.

### 2.2 본인인증 ↔ 회원 정책 (★ 2026-06-05 신규 결정)
- **비로그인 상태**: 본인인증 수행 (현행과 동일).
- **로그인 + 본인인증 완료 상태**: 본인인증 **생략**.
- **로그인 + 본인인증 미완료 상태**: 본인인증 수행 후 **회원 데이터에 반영**(인증결과를 회원 레코드에 저장).
- **유료진단은 회원만 가능.** (비회원은 무료까지만)

판정 로직(설계):
```
if not logged_in:
    → 본인인증 진행 (현행 anonymous 흐름)
    → 무료까지만 가능. 유료 진입 시 회원가입/로그인 유도
else:  # logged_in
    if member.identity_verified:
        → 본인인증 생략
    else:
        → 본인인증 진행 → member.identity_verified = true 저장
    → 유료 진단 가능
```

### 2.3 무료진단 (★ 유지 확정)
- 현행 흐름 유지: 섹터 → 기본정보 입력 → **주소 입력 → 건축물대장 일부정보 자동반영** → 무료진단 결과 → **유료 CTA 삽입**.
- 결제용 첨부파일(리포트) 다운로드 **현행 유지**.
- 무료는 비회원도 가능(본인인증만으로).

### 2.4 유료진단 (★ 회원 전용, 결제 선행)
순서:
1. **가격결정 정보 먼저 입력** (산업=상시근로자수 / 건물=연면적 / 건설=공사금액 + 업종·공사유형 등).
2. **가격 안내** + "이후 상세입력에 시간이 필요함"을 명확히 고지.
3. **결제 진행** (회원 확인 필수).
4. 결제 완료 → **나머지(시설·공정·설비) 입력**.
5. 입력 중 이탈해도 **로그인 값으로 이어서 입력**(재진입 복원). → 결제 후 입력은 회원 계정에 묶여 저장.

### 2.5 입력 방식 (★ 2026-06-05 신규 결정)
- SaaS의 공정·설비 입력은 **표준코드 기반 + 수동입력** 2가지 → 페이지가 복잡함.
- **법령진단에서는 수동입력 없음.** 표준코드 기반 입력만 제공(공정=표준 공정코드, 설비=표준 설비코드 검색·선택).
- 응답 타입: 현재 예/아니오/**모름**(tri_state 58개) → **"모름" 삭제, 예/아니오 2종(boolean)으로 통일.**

## 4. 신규 플로우 설계 (Step 재정의)

```
[가격표 페이지]  ← 선별용. 결제 버튼 아님
      │  "무료 진단 시작" / "유료 진단 시작"
      ▼
─────────────────────────────────────────────
[공통] 인증 게이트
   비로그인 → 본인인증(현행)         ─┐
   로그인+인증완료 → 생략             ├ 2.2 로직
   로그인+인증미완료 → 인증→회원반영  ─┘
─────────────────────────────────────────────
      ▼
Step1  섹터 선택 (현행 유지)
      ▼
┌──────────────[무료]──────────────┐   ┌──────────────[유료 · 회원전용]──────────────┐
│ Step2F 기본정보 입력             │   │ Step2P 가격결정 정보 입력                    │
│   주소 입력 → 건축물대장 자동반영 │   │   산업=상시근로자수 / 건물=연면적 /          │
│ Step3F 무료결과 + 유료 CTA       │   │   건설=공사금액 (+업종·공사유형)             │
│   결제용 첨부파일 다운(유지)     │   │ Step3P 가격 안내 + "상세입력 시간 필요" 고지 │
└──────────────────────────────────┘   │ Step4P 결제 (회원 확인)  ← ★ 선행            │
              │ 유료 CTA 클릭            │ Step5P 시설 입력 ─┐                          │
              └───── 회원 로그인 ──────▶ │ Step6P 공정 입력  ├ 표준코드만, 즉시저장,    │
                                         │ Step7P 설비 입력 ─┘ 이어하기(로그인 복원)    │
                                         │ Step8P 법령분석 (POST /diagnosis/run)        │
                                         │ Step9P 결과 + PDF + Excel                    │
                                         └──────────────────────────────────────────────┘
                                                       ▼
                                         [SaaS 시작하기] ← 재입력 없이 시설/공정/설비 승계
```

### 4.1 무료 진단 — **유지 확정** (이전 합의항목 ① 해소)
무료는 폐지하지 않는다. 현행 무료 흐름(주소→건축물대장→무료결과→유료 CTA→첨부 다운)을 유지한다. 무료는 비회원도 본인인증만으로 가능.

### 4.2 결제 후 입력 중단 — **이어하기 확정** (이전 합의항목 ② 해소)
유료는 회원 전용이므로, 결제 후 시설·공정·설비 입력 중 이탈해도 **로그인 계정에 묶인 세션으로 재진입하여 이어서 입력**한다. (별도 이메일 토큰 불필요 — 회원 인증으로 복원)

## 5. 작업 분해 (층) — 코드 변경 시 범위

### A층 — 프런트 플로우 재배치 (`taieng/nexas/free-diagnosis.html`)
- 인증 게이트 분기(2.2): 로그인 상태·회원 인증여부에 따라 본인인증 생략/수행.
- 유료 회원 게이트: 비회원 유료 진입 차단 → 로그인 유도.
- Step 순서 재정의(4절): 가격결정 입력 → 가격안내·시간고지 → 결제 → 상세입력.
- 응답 UI: tri_state(예/아니오/모름) → 예/아니오 2종 렌더.
- 표준코드 전용 입력: 수동입력 UI 제거(공정·설비 검색 선택만).
- 영향: 운영 사이트 1파일. Claude가 브랜치+PR 가능. (단 회원 로그인 상태 판정은 B/C층 API 의존)

### B층 — 가격 자동산정 API + 응답 타입 (`tai-api`)
- `GET /diagnosis/price-tier`(BUILDING 전용)를 3섹터로 확장: INDUSTRY=근로자수 구간, CONSTRUCTION=공사금액 구간, BUILDING=연면적(현행).
- `diagnosis_input_fields`의 tri_state 58개 → boolean 전환(모름 삭제). 데이터 마이그레이션 + 엔진의 tri_state 처리 분기 정리 필요.
- 가격 소스: `price_diagnosis_report`/`price_policy` 컬럼 구조 확인 후 결정([미확인 — 다음 단계 확인]).
- 영향: tai-api 라우터/서비스 + DB. Claude가 브랜치+PR 가능(모름 삭제는 엔진 영향 있어 GPT 확인 권장).

### C층 — 회원 연동 + 시설·공정·설비 공통모델 + SaaS 승계 (`tai-api` + DB)
- 회원 식별·인증여부 저장(`member.identity_verified` 등), 유료 진단 세션 ↔ 회원/factory_id 연결. 현재 무료/유료는 anonymous.
- 진단 입력을 SaaS 테이블과 통일. SaaS 측 존재 테이블(실측): `runtime_facility_profile`, `factory_process`, `equipment_assets`, `process_equipment_map`, `facility_condition`, `runtime_facility_equipment`, `v_facility/process/equipment` 뷰.
- 결제 후 입력 즉시 저장 + 회원 계정 기반 이어하기 복원.
- "SaaS 시작하기" 시 동일 레코드 승계(재입력 금지).
- 영향: **회원/인증 + DB 스키마 + 엔진 입력 + SaaS 동시.** 법해석·엔진 구조와 얽혀 **GPT와 분담 필요.** Claude 단독 운영 DB 적용 보류.
