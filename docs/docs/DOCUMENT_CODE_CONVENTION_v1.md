# 문서 코드 규정 (Document Code Convention) v1

> 상태: 확정 초안 (operator 승인 대기 항목 명시)
> 작성일: 2026-08-22
> 범위: TAI Safe 문서엔진 — 서식 유형/발행 문서 식별자 규정
> 배경: 오픈 전 · 기존 발행 데이터는 목업 → 하위호환 제약 없음, 지금 깨끗이 확정

---

## 0. 규정을 정하는 이유

현재 세 테이블이 서로 다른 코드 체계를 쓴다(실측).

| 테이블 | 역할 | 코드 체계 | 예 |
|---|---|---|---|
| document_forms (260) | 전수조사 카탈로그(무엇이 필요한지 지도) | DOC-{도메인}-{번호} | DOC-OSH-007 |
| form_templates (11) | 법정 별지 서식(관공서 제출) | OSHACT-FORM-{번호} | OSHACT-FORM-030 |
| document_form_master (63) | TAI 표준·자유서식(생성 대상) | {의무}-{대상}-{번호} | INSPECT-ELEC-01 |

같은 문서가 테이블마다 다른 코드를 가질 수 있어, 템플릿 파일명·DB·화면이 어긋난다.
이를 막기 위해 발행 문서와 서식 유형의 식별자 규정을 통일한다.

---

## 1. 핵심 원칙 (LEG 교훈 계승)

- 코드는 **식별자**다. 분류(도메인·섹터·등급·법근거)는 코드가 아니라 **컬럼**(sector·tai_grade·law_ref)이 담는다.
- 코드에 자주 바뀌는 분류를 박지 않는다 → 재분류해도 코드가 붕괴하지 않는다.
- 단, "제목만 보고 무슨 문서인지 안다"는 요구를 위해 **유형 약어는 의미 있는 영문**으로 둔다.
- 영문 약어 이유: 파일명·경로·파싱 안전. 화면 제목은 별도 한글 이름을 둔다.

---

## 2. 두 층위 규정

### 층위 1 — 서식 유형 (종류당 1개, 날짜 없음, 안정 식별자)

형식: `DOC-{TYPE}`

| TYPE | 서식 유형 | 대표 문서 | 데이터 소스 |
|---|---|---|---|
| INSP | 안전점검일지 | OSH-007·038, CON-007, CON-LAW-014 | inspections |
| CHK | 점검 체크리스트 | OSH-017·055 | inspections/법령엔진 |
| EQUIP | 설비점검기록부 | 소방·전기·승강기·가스·보일러 등 15건 | inspections |
| TBM | 작업 전 안전점검회의(TBM) | OSH-056, CON-012 | TBM모듈 |
| PPE | 보호구 착용 점검 | OSH-046 | inspections |
| CONLOG | 공사일지(법정 별지) | CON-006 | factory/inspections |
| APPT | 선임 보고 | OSH-062·063 | (신고성, 데이터 없음) |
| EDU | 교육일지 (보류: 교육 모듈 미운영) | OSH-006·037, SERA-006 | 교육모듈 |

### 층위 2 — 발행 문서 (실제 출력물 한 건, 날짜 포함)

형식: `{TYPE}-{사업장}-{YYYYMMDD}[-{세부}]`

- 세부가 없는 문서: `INSP-A공장-20260822`
- 세부가 필요한 문서만 **날짜 뒤에** 세부를 붙인다: `EQUIP-A공장-20260822-ELEC`
- 세부를 날짜 뒤에 두는 이유: 유형 코드를 짧고 안정적으로 유지하고, 세부(설비 대상 등)는 필요할 때만 확장. 설비 종류가 늘어도 유형 코드는 불변.

### 화면 제목 (사람이 읽는 이름)

예: `안전점검일지 · A공장 · 2026-08-22`, `전기설비 점검기록부 · A공장 · 2026-08-22`

---

## 3. 설비점검 세부(대상) 코드표

EQUIP 유형은 대상 설비를 세부로 둔다(날짜 뒤). 대상별 법 근거·점검항목이 달라 세부로 구분한다.

| 세부 | 설비 대상 | 근거 예 |
|---|---|---|
| FIRE | 소방시설 | 소방시설법 제25조 |
| ELEC | 전기설비 | 전기안전관리법 제11조 |
| ELEV | 승강기 | 승강기안전관리법 제17조 |
| GAS | 가스시설 | 고압가스안전관리법 제17조 |
| HAZMAT | 위험물·유해화학물질 | 위험물안전관리법 제18조 |
| BOILER | 보일러 | 에너지이용합리화법 |
| REFRIG | 냉동기 | — |
| ASBESTOS | 석면 | — |
| MACHINE | 기계설비 | 산안법 제38조 |
| CRANE | 타워크레인 | 산안법 |
| SCAFFOLD | 비계 | 산안법 제38조 |
| GUARD | 방호조치 | 산안법 제38조 |

> 세부 코드는 신규 설비 등장 시 이 표에 추가하는 방식으로 확장(유형 코드 무변경).

---

## 4. 템플릿·저장 연계

- 렌더 템플릿 파일명 = 유형 코드 기준: `templates/documents/DOC-{TYPE}.html` (EQUIP은 유형 1템플릿 + 대상 데이터 주입).
- 생성형 문서: 실물 PDF 저장 안 함, 호출 시 렌더링(자원 절약).
- 확정본(이전 제출 문서): 발행 코드로 문서함에 쌓되 그 시점 PDF/원본을 스냅샷 보관(storage_ref).

---

## 5. operator 결정/확인 필요

- [확정] 유형 약어 = 영문 의미 약어.
- [확정] 발행 코드 = TYPE-사업장-YYYYMMDD-[세부], 세부는 날짜 뒤.
- [확인 필요] EQUIP "유형 1템플릿 + 대상 데이터 주입"이 성립하려면 대상별 점검항목이 데이터(safety_inspection_results)로 관리되는지 첫 템플릿 제작 시 실측.
- [확인 필요] 세 테이블 통합 vs 매핑 참조: 본 규정은 유형/발행 식별자만 확정. 카탈로그(document_forms)·법정별지(form_templates)·마스터(document_form_master) 물리 통합 여부는 별도 결정.
